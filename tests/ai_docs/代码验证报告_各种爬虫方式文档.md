### 2. ❌ 发现的问题 (幻觉/错误)

#### 2.1 `fabric_deploy` 参数错误
- **文档代码** (Line 353):
  ```python
  crawl.fabric_deploy(
      ...
      process_count=4  # <--- 错误参数名
  )
  ```
- **源码定义** (funboost/core/booster.py):
  ```python
  def fabric_deploy(self, ..., process_num = 1, ...):
  ```
- **结论**：应将 `process_count` 修正为 **`process_num`**。

#### 2.2 `funboost.workflow` 模块存在 (验证通过)
- **文档代码** (Line 465):
  ```python
  from funboost.workflow import chain, group, chord, WorkflowBoosterParams
  ```
- **验证**：在 `D:\codes\funboost\funboost\workflow` 找到了该模块，且导出 `chain`, `group`, `chord`。
- **结论**：文档描述正确，非幻觉。之前因未索引到 `D:\codes\funboost` 导致误判。

#### 2.3 `TaskOptions` 优先级参数需确认
- **文档代码** (Line 435):
  ```python
  TaskOptions(other_extra_params={'priority': 9})
  ```
- **验证**：`TaskOptions` 确实有 `other_extra_params` 字段，但 `priority` 是否生效取决于具体的 Broker 实现（如 RabbitMQ）。教程中提及 "需要中间件支持优先级"，这在逻辑上是自洽的，但需注意 Redis 默认通常不支持 RabbitMQ 风格的 priority 字段，除非使用 `REDIS_PRIORITY` broker kind。
- **建议**：保留但需注意 Broker 类型。
